Общий вердикт: код готов к демо, но не к продакшену — и это нормально для хакатона

За 1,5 дня (28–29.10) собран рабочий вертикальный срез: гость (текст+голос) → AI-роутинг → сохранение → staff-борд → live-обновление. Код чистый, типы строгие, коммиты атомарные и подписанные. Критических уязвимостей нет. Архитектурные упрощения (JSON-файл вместо БД, отсутствие auth) осознанные и задокументированы. Главные риски — отсутствие тестов/защиты ветки и незапушенные коммиты (проверьте push).

✅ Сильные стороны

Строгий TypeScript, валидация на входе и выходе, честный MOCK-фолбэк, продуманный UX (правка голоса, приватность, бейджи), responsive 375→1440, атомарные коммиты.

⚠️ Зоны внимания

Нет тестов, нет CI, нет защиты ветки, 3 последних коммита требуют проверки push, файл-хранилище и отсутствие auth — демо-only, нужен деплой-план к дедлайну.

6 — API-роуты (src/app/api)
POST /api/guest/messageroute.ts · 4 755 BПроверен

Что делает: принимает {message, room} → валидирует (пусто / >2000 симв) → если нет MODEL_API_KEY — возвращает mode: "MOCK" c mockTasks(); иначе — вызов POST https://api.meta.ai/v1/chat/completions (muse-spark-1.3, temp 0.2) → парсит JSON (с защитой от markdown-обёрток) → validateTasks() → сохраняет через createStoredTasks() → {mode:"LIVE", tasks}.

  • ✓ Вход: 400 на пустое / >2000 симв, trim + slice room до 20 симв.
  • ✓ Выход: validateTasks отбрасывает мусор, max 10 задач.
  • ✓ Ошибки: 502 с дружелюбным текстом + console.error (без ключа).
  • ✓ Секреты: только process.env.MODEL_API_KEY, не в коде.

⚠ Замечания

  • Нет rate limiting — любой может спамить POST и создавать задачи. Для демо ок, для прод — нужен лимит (IP/window).
  • Нет аутентификации — guest-роут открыт; осознанно для QR-демо, но стоит коммент «demo-only».
  • MOCK по отсутствию ключа — удобно, но в проде лучше явный флаг MOCK=true, а не «нет ключа → фейк».
POST /api/guest/transcriberoute.ts · 4 141 BПроверен

Что делает: принимает multipart/form-data {audio} → 503 без ключа → 400 без аудио → 413 >10 МБ → 415 не-WAV → проксирует в POST https://api.meta.ai/v1/asr/transcribe (muse-voice-transcribe-1.0, WAV, PUSH_TO_TALK) → {transcript, language, languageSource, model}.

  • ✓ Проверки: 503/400/413/415/502/422 — полный набор.
  • ✓ WAV-валидация по RIFF/WAVE заголовкам — защита от мусора.
  • ✓ Сообщения: дружелюбные, на английском, с подсказкой «type instead».
  • ⚠ Нет ограничения на частоту — транскрибация дороже text API; один гость может нагрузить ключ.
GET /api/tasks + DELETE /api/tasksroute.ts · 814 BПроверен

GET: ?room=<id>&department=<dept>&ids=<csv> → listStoredTasks(filter) → sortTasks() (urgent→newest) → {tasks}. Поддержка ids (до 50) для приватного polling гостя.

DELETE: clearStoredTasks() → {ok, cleared} — для кнопки Reset demo data.

  • ✓ Фильтры корректны, slice(0,50) на ids — защита от огромных query.
  • ✓ Сортировка на сервере — консистентна для всех клиентов.

🔴 Критическая находка

DELETE без авторизации. Любой, кто знает URL, может стереть все задачи. Для хакатона допустимо, но это единственный роут с деструктивным действием без проверки. Рекомендация — добавить хотя бы проверку Origin или временный токен, либо скрыть кнопку после демо.

PATCH /api/tasks/[id][id]/route.ts · 1 630 BПроверен

Что делает: PATCH /api/tasks/:id {status | action} → мапит accept/start/done → updateStoredTaskStatus() → 400 (неверный статус) / 404 (нет задачи) / 409 (неверный переход) / 200 (обновлена).

  • ✓ Строгий FSM: new → accepted → in_progress → done — пропуск запрещён (409).
  • ✓ Поддержка обоих форматов: {status:"accepted"} и {action:"accept"} — гибкость.
  • ✓ Сообщения 400/409 объясняют допустимый flow — хорошая DX.
  • ⚠ Нет проверки department — любой staff может двигать любую задачу (не только своей команды). Фильтр только на фронте.

lib/store.ts3 888 BПроверен

Что делает: JSON-хранилище .data/tasks.json — readAll/writeAll (atomic через .tmp + rename), listStoredTasks, createStoredTasks, updateStoredTaskStatus (FSM), clearStoredTasks. Есть очередь withLock для сериализации read-modify-write.

  • ✓ Atomic write (tmp→rename) — защита от полузаписанных файлов.
  • ✓ withLock — защита от race при параллельных запросах.
  • ✓ isStoredTask — валидация при чтении, битые записи отбрасываются.

⚠ Замечания · Архитектурное ограничение

Файл вместо БД — demo-only. При падении процесса, деплое или масштабировании (2 инстанса) данные потеряются/разойдутся. Это осознанный выбор для хакатона, но в README стоит явно пометить секцию «Storage: file-based, demo only».

lib/language.ts3 612 BПроверен

Что делает: guessLanguage(text) — эвристика по скриптам (кириллица→ru, арабский→ar, и т.д.) + по стоп-словам (en/es/fr/de/it/pt/tr/kk). languageFromMeta(data) — читает language/detectedLanguage из ответа Meta, если появится.

  • ✓ Fallback на случай, если Meta добавит поле языка — продумано.
  • ✓ Поддержка казахского (kk) — плюс для локального рынка.
  • ⚠ Эвристика хрупкая — короткий текст «Help!» → en по стоп-словам, но «Көмек!» (казахский) может не распознаться. Для демо ок; LIVE-транскрибация обычно возвращает корректный язык.

6 Нет валидации room-параметра на фронте src/app/r/[room]/page.tsx Low URL /r/<script> отрендерит Room <script> — не XSS (React экранирует), но некорректный UX. Бэкенд slice(0,20) спасает.
7 Нет CSRF-токена Все POST/PATCH/DELETE Low Для хакатона не требуется (нет cookies/auth), но в проде с сессиями — нужен.
8 Caret-зависимости (^) package.json Low Может подтянуть breaking-минор при npm install. Mitigated by package-lock.json.

ℹ Контекст

Критических (Critical) уязвимостей — 0. Все находки — уровня High и ниже, типичные для хакатон-MVP без auth/БД. Ни одна не требует немедленного фикса до дедлайна; они документируются как known limitations. Единственное действие до сабмита — убедиться, что DELETE не доступен извне прод-деплоя (или скрыть кнопку Reset).
